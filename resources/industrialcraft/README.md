  - 農業と酒造は作物 (通常品種、改良品種)、農業道具、酒造関連アイテム

## 2. 用語解説 (wiki より抜粋要約)

### 2.1. EU関連

- EU (Energy Unit): IC2 における電力の単位. 整数値. 発電機が生み出し、各種ブロック、アイテムの加工に消費される
- EU/t (Energy Unit per tick): 単位時間あたりの生成量、送電量、消費量. 1 tick = 1/20 秒. ECメーターで測定可能. 機械の最低動作可能入力はこの値で定義される
- EU-Packet (EU-P): EU はまとまった値の塊で送電され、その塊が EU-Packet. この大きさで低圧、高圧などの電圧が決まる. 32EU-P は32EUが1塊のパケット1つを意味し、32個ではない. 送電線の損失率は EU-P ごとに計算される
- EU/t と EU-P の違いに注意: 32EU-P で 32EU/t の発電機が16機繋がったケーブルは、消費先があれば 32*16=512EU/t を送電できるが規格は 32EU-P のまま (低圧規格のケーブルは蒸発しない)
- 減衰 (損失): ケーブルには減衰率があり EU/B (EU per Block) で表される. 1ブロック通過ごとに EU-P がその値分小さくなる
- 電圧の5段階:
  - 超低圧 (5EU-P以下): スズ製ケーブルの許容最大. 一部低出力発電機用
  - 低圧 (32EU-P以下): 銅ケーブルと一般的な機械の許容最大. 非絶縁ケーブルはほぼ確実に感電
  - 中圧 (128EU-P以下): 金ケーブルと一部上位機械. 1回被覆の金ケーブルでは感電を防げない
  - 高圧 (512EU-P以下): グラスファイバーと一部上位機械
  - 超高圧 (2048EU-P以下): 精錬鉄製ケーブル (HVケーブル). 対応装置は存在せず長距離送電専用
- 減衰は EU-P の塊ごとにかかるため、パケットを大きくまとめた方が損失は小さい (高圧化する方が効率的). ただし超高圧については HVケーブルよりグラスファイバーで高圧送電する方が良い (wiki 掲載の計算例: 200ブロックに2048EUを送る場合、HVケーブル超高圧で1888EU到達 vs グラスファイバー高圧4パケットで2028EU到達)

### 2.2. EU関連語の補足

- 出力側: 発電機の電圧は出力に等しい. 蓄電器、変電器は蓄積が規定出力以上にならないと出力しない (BatBox は31EU以下では送電せず32EU以上で32EU/t出力). 出力EU-P以下の入力しかない場合は断続的に出力される
- ケーブル: EU-P が規格以下なら電流をいくら流しても蒸発しない. 銅ケーブルに BatBox4個から32EU-Pずつ出力すれば128EU/t流せるが、MFE から128EU-Pを直接出力すると蒸発する
- たとえ話 (英wikiより): EU-Packet は"小さいおっさん"、ケーブルはトンネル. トンネルよりおっさんが大きいと爆発 (蒸発). 変圧器で大きいおっさんを小さいおっさん4人に分割できる

### 2.3. 原子炉関連

- 熱量 (Heat): ウランセルから発生する熱. 単位は H、1 Reactor Tick 毎の排熱量を Heat/second で表す. 原子炉、チャンバー、冷却セル、放熱板などの内部パーツは熱を格納でき、限界を超えると消耗、融解してメルトダウンの恐れ
- 冷却 (Cooling): 冷却セル、排熱口、コンデンサ等で行う. 単位も H、Reactor Tick 毎の冷却を Heat/second
- リアクターチック (Reactor Tick): EUのtickと違い 1 Reactor Tick = 1秒. 熱量と冷却の発生タイミングは全てこれ
- ウランパルス (Uranium Pulse): 稼働中ウランセルは1Tickごとに1パルス発生. 隣接ウランセルにパルスが当たると更に1パルス生み出す. 隣接2個なら合計4パルス
- フルサイクル (Full Cycle): ウランセル1個が完全に消化しきること. 10,000 ReactorTick (2時間47分)
- クールダウン期間 (Cooldown Period): 内部コンポーネントに蓄積した熱量を放熱させるのに必要な時間
- 原子炉外殻 (Reactor Hull): 内部パーツがない、冷却できない場合に原子炉が熱を蓄積. デフォルト最大耐熱値は 10,000 Hull、融解開始温度は 8,500 Hull. リアクタープレートで補強可能
- 大爆発 (Violent explosion): 融解すると炉外へ熱が漏れ水は蒸発、木は炎上、石は溶岩化. 爆発力は Config デフォルトで TNT=4、核爆弾=35、原子炉=45. 爆発半径は約25ブロックの球体
- 原子炉の等級 (Reactor Class):
  - Mark I-I: 安全かつ低発電力. サブクラスIは外部冷却不要
  - Mark I-O: 同上だが外部冷却に依存
  - Mark II: 炉内温度85%に達するまで最低1サイクル可能. 消化後クールダウン必要. サブクラス数字は消化できるウランセル回数
  - Mark III: 安全性を犠牲にしレッドストーン動力で定期停止が必要. 1サイクルの10% (16分40秒) 完遂が条件
  - Mark IV: Mark IIIと同条件だが最悪各種部品が壊れても良い
  - Mark V: 排熱のため停止が必要だが、長時間かけて燃料を完全消化できる
- 使い捨て冷却 (SingleUseCoolant): クラス維持に氷ブロックや水バケツを使う場合、クラス末尾に -SUC と表記
- 原子炉の効率 (Reactor Efficiency): 発電効率 = 総パルス回数 / 総ウランセル数. ランクは EE (1.0) < ED (<2.0) < EC (<3.0) < EB (<4.0) < EA (4.0以上) < EA+ (<6.0) < EA++ (<7.0) < EA* (7以上)

## 3. ソースコードとアセットの所在

- 公式 GitHub org `IndustrialCraftMC/IndustrialCraft2` は存在するが、言語ファイル管理とコミュニティ (バグ報告、要望) 用途で、MOD 本体のソースコードは公開されていない
- 実体は Jenkins (jenkins.ic2.player.to) と Maven (maven2.ic2.player.to / maven.ic2.player.to) でコンパイル済み jar、dev jar として配布されている
- アセット (テクスチャ、モデル、lang) は jar 内部の `assets/` 以下に入っているため、jar をダウンロードして展開すれば取得可能. 必要になったら該当バージョンの jar を Maven から取得して展開する
- API ドキュメントは http://ic2api.player.to/ic2api/html/annotated.html

### 3.1. IC2 Classic の assets/data 取得済み (2026-10 追記)

- IC2 系は IC2 Classic (Speiger 版) を採用し、CurseForge 配布の `IC2Classic-1.19.2-2.1.3.4.jar` から `assets/` (4521ファイル) と `data/` (loot_tables, loot_modifiers, biome_modifier) を展開して `assets/`, `data/` に配置済み
- `TinyModularThings/IC2Classic` (GitHub) は API とバグトラッカーのみで実装ソースは非公開. クラフトレシピは `data/ic2/recipes` ではなく jar 内コード (`IC2Recipes.addRecipes`) に登録されるため、CFR で逆コンパイルし `recipes_export.json` (917件) として機械抽出した
- 機械レシピ (粉砕機、抽出機、圧縮機、合金炉、精製機等) も同様に `TileEntity::loadRecipes` から `machine_recipes_export.json` (188件) として抽出済み
- ITEMS.md の各アイテムには、抽出レシピを `公式レシピ` 行として併記済み (lang で英名と item id を対応付け. IC2C と旧 IC2 で名称が違う項目は未対応)
- 注意: BCN の仕様正本は ITEMS.md (旧 IC2 = Experimental 系) であり、IC2C のデータは近似参照として扱うこと (ユーザー決定)
