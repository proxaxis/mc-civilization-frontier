# タスク: 環境構築・起動検証

あなたは Minecraft MOD パックプロジェクト "Civilization Frontier: Beyond the Cataclysm" の作業エージェントです. このタスクは全作業の前提となるサーバー起動環境の整備と、MOD 群の実動検証です.

## 前提知識

* ワークスペース: `/ws`
* Minecraft Java Edition `26.3`、Mod Loader は Fabric、サーバー・クライアント双方想定
* MOD jar は `/ws/resources/mods/` に 78 本配置済み(依存関係は解決済み)
* 導入 MOD の全体像は `/ws/docs/MOD_LIST.md` を参照
* サーバー定義は `/ws/docker-compose.yml` と `/ws/Dockerfile.testserver`
  * `itzg/minecraft-server:latest`、TYPE=FABRIC、VERSION=26.3、EULA=TRUE、RCON 有効
  * 現状 `resources/mods` はコンテナへマウントされていない
* RPG 系 MOD(Spell Engine、Paladins、Wizards、Rogues、Arsenal 等)の `fabric.mod.json` は `java>=25` を要求する
* Incendium(ネザー改修)は生成系が他と競合しうるので実地確認が必要

## 目的

MOD パックが実際に起動し、ワールド生成まで通る状態を作る.

## タスク詳細

1. `docker-compose.yml` の testserver サービスに `./resources/mods:/data/mods` のボリュームを追加する(読み取り専用でよい)
2. `itzg/minecraft-server` イメージの Java バージョンを確認する. 25 未満なら対応するタグへ差し替える
3. `docker compose up testserver` で起動し、以下を確認する
   * mod ロード時の依存エラーやクラッシュがないこと
   * mixin 競合による起動失敗がないこと
   * ワールド生成が完了すること
4. 生成されたワールドで主要構造物(MOD 由来の構造物、特に Incendium)が生成されるかを確認する. 確認手段は `/locate structure` や実際の探索でよい
5. 余裕があれば以下も確認する
   * 構造物の生成頻度が過密になっていないか
   * Undead Nights の夜襲周期と編成の現在設定(設定ファイルの場所と内容)
   * 構造物 MOD のチェストが Lootr で個別ルート化されるか

## 制約・注意点

* 破壊的な変更(既存ファイルの削除、マウントでないワールドデータの削除)は行わない
* 結果は起動ログと確認項目の成否で報告する

## 完了条件

* `resources/mods` がマウントされ、全 MOD 込みでサーバーが起動してワールド生成まで通る
* 未解決のエラーや競合があれば内容を記録して報告する
