# Task: 残検証項目(クライアント実機 + 設計フェーズ)

## 目的

Task 106 の後続として、サーバー側で検証できない残項目を潰す.
導線(職業選択→スキル→魔法→戦闘)は構造的に実装済みだが、個別発動確認とクライアント UI 目視は未完了.

## 検証項目

### A. 全 60 スペルの個別発動確認(クライアント必須)

* 現状: firebolt のみ実機完走(ルーン消費・疲労度・発射を実測)
* 残 59 種は JSON 妥当・スキーマ正本照合済みだが個別発動は未確認
* 方法: 各職業の "全結合書" を装備し、スロットキーで順に発動. 装備差し替え・消費計測・効果判定は RCON 側で補助可能
* 特に確認したいもの: TELEPORT(blink, shadow_strike)、VELOCITY(dash)、AGGRO(taunt)、SPAWN(clone)、FIRE 付与、サモン/構造物影響系

### B. 自動キャスト経路の限界(調査済み)

* `/bcn_cast` コマンドは ServerNetwork.handleCastRequest を受理させられるが、fake player ではキャストプロセスが完了しない
* ServerPlayer は SpellCastInteractor を直接実装しない(isInstance=false)
* 結論: 発動検証はクライアントのスロットキー必須. サーバー側自動化は不可

### C. 結合台 UI の目視確認

* spell_book タグ空による購入封じは設計上成立しているが、UI での非表示は未目視
* 確認: 結合台に本+ラピスを入れて cfb スペルが購入候補に出ないこと

### D. 巻物譲渡による未習得使用(設計限界)

* 巻物は item なので未習得者にも渡れば使用可能. 完全ロックは spell_engine 側拡張が必要
* 要判断: 許容するか、spell_engine の spell_pool/learn 制約で対応するか

### E. 構造物への敵自動出現トリガー(未配線)

* 現状は set_* 関数の手動呼び出しのみ. 構造物侵入検知やスポナー配置との連携がない
* 案: 構造物タグ検知 + 構造ブロックスポナー設置、または Flan/claim 連携

### F. 数値・バランス調整

* EFP 閾値(12/30/60)・維持費額・クエスト報酬額は仮値
* クールダウン 0.6 倍は実機で妥当性要確認
* 影分身: おとりは villager で近似. 名前タグ・外見を本実装に寄せるか要判断

## 完了条件

* A: 全 60 スペルで発動・消費・効果の確認結果が記録されている
* C: 購入封じが UI で機能していることが確認されている
* D-F: 各項目が「対応済み」または「方針決定済み(対応しない判断含む)」
